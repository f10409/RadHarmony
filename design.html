    Design decisions¶

    This page records the design choices of RadHarmony and the reason for each choice. Use it to answer the question "is this a bug, or is it how we want it?".

    • Contributors: read it before you add a dataset, a backbone or an evaluator.
    • Review agents: compare the code with these decisions. If no decision covers a behavior and you cannot tell if it is a bug, write an open question (see the review briefs). Do not guess the intent.

    Related pages: Concepts shows how the layers work. The file eval/RULES.md in the repo has the review rules (J-xx) and the lesson checks (L-xxx). The folder docs/proposals/ has the design drafts.

    How to read an entry¶

    Each decision has an ID (D-xx) and these lines:

    • Status:
    • Decided means that a maintainer chose it. The entry names the person and date, or the file that records it.
    • Decided, planned means that a maintainer chose it, but the feature is not built yet. Do not report the missing feature as a bug.
    • Decided by the agent, for Frank Li to confirm means that an agent chose its recommended option. This was in the fix stage that started on 2026-11-01, and for Q-9 to Q-20 and the draft rules of the 2026-11-02 review. Frank Li asked for it both times. Treat it as decided until Frank Li confirms or changes it.
    • From the code means that the code does it today, but no maintainer has confirmed it yet. Treat it as the intent until a maintainer confirms or changes it.
    • Open means that a maintainer has not decided yet. The entry gives the question, what the code does today, the options and the evidence (a command and its output, or a file and line). It has no "Known gaps" line. Do not report the behavior as a bug. When a maintainer decides, the status changes, and the ID stays the same.
    • Checked by: the review rule, lesson or test that checks it, or "none".
    • Known gaps: places where the code breaks the decision today, one line each, with the finding ID. A gap is a bug to fix, not a reason to change the decision. An ID (for example V-H1-23) always names the same finding, in every run. reports/eval/index.json gives its run folder. The index and the folder are local only (not in git). "No ID" means that a maintainer found the gap by reading the code, and no report has it yet. Some gaps have more details in eval/TODO.md, section 2. /fix removes a gap when it fixes it. A gap whose fix needs a base-code change names its strict xfail test, if one exists.
    • Open part: a detail of a decided entry that is not decided yet. It gives the question, an example and the options.
    • Notes: facts that help, but that are not gaps.
    • Related: other entries about the same topic.

    An ID never changes. A new decision gets the next free D- number, and it goes in the section where it belongs. So the numbers in a section are not in order. Use the index to find an ID.

    Words on this page:

    • Table: the harmonized_df that a harmonizer makes.
    • Harmonizer: a class that reads the source files and makes the table.
    • Dataset class: a class that reads the table and gives samples (ds[i]).
    • Official split: a train, validation or test set that the dataset authors provide.
    • Bootstrap sample: one draw, with replacement, from the test set.
    • Open question: a behavior that no decision covers. A review agent writes it in its report (Q- ID). A maintainer decides it, or it becomes an entry with the status "Open".
    • Open part: a detail of a decided entry that is not decided yet. For example, D-29 had one until 2026-10-30: which threshold zero-shot uses.

    Table¶

    D-01 One table is the contract¶

    harmonize() returns the table as one pandas DataFrame. After harmonize(), no class reads the source CSV or JSON files again. The dataset classes, the app and the evaluators read only the table.

    • Required columns: patient_id, study_id, image_path.
    • Optional columns: series_id, view_position, mask_path, bbox, bbox_labels, report, age_years, sex, the label columns, the regression columns (REG_COLS) and the extra columns (EXTRA_OUTPUT_COLS).
    • Planned optional columns (D-31): study_date, study_time and visit_number. They are NaN when the source has no value.

    Why: one format lets a dataset class, a probe or the app work with every dataset.

    • Status: From the code (_select_harmonized_columns in radharmony/harmonizer/base.py).
    • Checked by: J-02.
    • Source IDs: study_id keeps the study ID of the source, also when the source gives one ID to 2 patients. The harmonizer then warns. Code that groups by study uses (patient_id, study_id), as D-31 does. Example: BRAX keeps the AccessionNumber, and 2 of its 23,276 values belong to 2 patients each. Decided (Frank Li, 2026-10-30, V-H1-9). The other option was the BRAX Study_<UID> folder name (23,278 values, 1 patient each). PadChest also warns since 2026-11-03: 1 StudyID belongs to 2 patients (V-H2-32). Both use warn_shared_study_ids in radharmony/harmonizer/_ids.py. Checked by: tests/test_padchest.py.
    • MedPMC answer: the release index has no caption, so the caption comes from our tag table (scripts/build_medpmc_tags.py). With no tag table, answer is None in every row, and the harmonizer warns. The images still work. Decided (Frank Li, 2026-10-30, V-H1-27). The other options were an error, and an error with a new argument to turn it off. Checked by tests/test_harmonizer_data.py::test_medpmc_without_tag_table_warns_that_answer_is_empty.
    • MedPMC include_multipanel=False: a specialty filter drops the multipanel rows, because their tag comes from the caption of the whole figure. Without a specialty filter, the flag does nothing. Example: the multipanel radiology rows go from 513,709 to 0. Before 2026-11-03, the flag did nothing, because the tag table has no contains_specialty column. Decided by the agent, for Frank Li to confirm (2026-11-03, V-H1-47). The other options were to drop the flag, and to drop every multipanel row also with no specialty filter. Checked by: tests/test_medpmc.py::test_include_multipanel_false_gives_a_panel_level_set.
    • MIMIC IDs: every harmonizer on MIMIC images writes patient_id and study_id as digits, the official MIMIC IDs (for example 10003502, not p10003502). So a join across these datasets works. Decided (Frank Li, 2026-10-31, Q-12 of the 2026-10-31 review). The other option was the source form of each dataset, on its wiki page. Since 2026-11-01, GEMeX VQA and MIMIC-Ext-CXR-QBA write digits (Q-12). The study_ids= and patient_ids= filters of MIMIC-Ext-CXR-QBA accept both forms. Checked by: tests/test_harmonizer_id_filter.py::test_mimic_ext_qba_ids_are_digits_and_question_id_names_one_row and ::test_gemex_vqa_ids_are_digits.
    • VQA row id: the question_id of MIMIC-Ext-CXR-QBA is <study_id>_<source question_id>, because the source id is a template name that repeats in every study (V-H1-30). Example: 50037760_D01_describe_finding_015. Decided (Frank Li confirmed on 2026-11-02 the choice of the agent of 2026-11-01). The other option was the source id with a separate row number.
    • VQA row id of CheXinstruct VQA: unique_id of the compiled JSON. The MIMIC-CXR-VQA processor shuffles the train questions with no seed, so scripts/compile_chexinstruct_vqa.py seeds random (--seed, default 0). 2 runs with the same seed then give the same file. The JSON on the NAS came from a run with no seed, and it stays. A new run gives the same 701,458 questions, answers, images and splits. Only the unique_id and the order of the MIMIC-CXR-VQA train rows change, and the qa_pair of the closed questions. The harmonizer does not read qa_pair. Decided (Frank Li, 2026-11-04). The other options were a seed and a new NAS file, and no seed. Checked by: tests/test_scripts.py::test_compile_chexinstruct_vqa_seed_gives_the_same_file.
    • 3-D view_position: the name of the nearest plane ("axial", "coronal" or "sagittal"), from the DICOM ImageOrientationPatient. The vector goes in the extra column image_orientation. Example: CT-RATE. Decided (Frank Li, 2026-10-30, V-H1-28). The other options were the vector only, and the plane name with no vector column.
    • Checked by (3-D view_position): tests/test_harmonizer_data.py::test_ct_rate_view_position_is_the_nearest_plane and ::test_ct_rate_orientation_count_on_nas.
    • Known gaps (3-D view_position): 3 harmonizers do not read ImageOrientationPatient, so their tables have no view_position. They are RSNA 2022 cervical spine, RSNA 2023 abdominal trauma and RSNA PE detection. The DICOM headers have the tag. Found in the 6c rewrite of the wiki pages (2026-11-04). The fix is in their own harmonizers, not in base code.
    • RSNA 2024 lumbar spine follows the 3-D rule: view_position is "axial" or "sagittal". The series description ("Axial T2", "Sagittal T1", "Sagittal T2/STIR") goes to the column series_description. series_filter reads that column, with the same values as before. Decided (Frank Li, 2026-10-31, Q-18 of the 2026-10-31 review), with a note from Frank Li: revisit this later. The other option was an exception for datasets with a description. Known gap: view_position holds the description today (Q-18). The description agrees with the orientation in 300 of 300 random series.
    • 2-D view_position: one shared name list, as for sex (D-26). The names are PA, AP and LATERAL, and NaN means unknown (for example a blank, Unknown, UNK, N/A or EXCLUDE). A source with AP or PA gives AP or PA, not Frontal. Any other source value (for example an oblique view or AP_horizontal) keeps its raw value in upper case. One base step does the mapping. Decided (Frank Li, 2026-10-31, Q-13 of the 2026-10-31 review). The other option was the raw values of each source, listed on each wiki page.
    • 2-D view_position step: _build_view_position_names in radharmony/harmonizer/base.py (base code, approved by Frank Li on 2026-11-02). L, LL, RL and LAT give LATERAL, POSTERO_ANTERIOR gives PA, ANTERO_POSTERIOR gives AP, and the text None gives NaN. A class with VIEW_POSITION_NAMES = False keeps its own names: CT-RATE and RSNA 2024 lumbar (3-D plane or series names) and Emory CXR DICOM. Checked by: tests/test_view_position.py. On 2026-11-02 the real counts matched the source, for example BRAX LATERAL = 9,052 L + 1,340 RL. A table saved before 2026-11-02 keeps its old names until harmonize() runs again.
    • Notes (2-D view_position step): since 2026-11-03, base code approved by Frank Li, ANTERO_POSTERIOR gives AP and the text None gives NaN (V-H2-43). Before, they gave ANTERO_POSTERIOR and NONE. The ReXGradient train JSON has 1 ANTERO_POSTERIOR view and 2 text None views. Checked by: tests/test_view_position.py::test_unknown_strings_give_nan_and_an_opt_out_class_keeps_them.
    • CheXpert, CheXpert Plus and CheXphoto view_position: a frontal image with LL or RL in AP/PA gives NaN, because AP or PA is unknown. CheXpert train has 17 such images. This follows the Emory rule of Q-14. Decided (Frank Li confirmed on 2026-11-02 the choice of the agent). The other options were LATERAL from the shared table, and the source value LL or RL.
    • Known gaps (2-D view_position): these harmonizers write FRONTAL where the source has AP or PA (Q-13). CheXlocalize val has AP or PA in its CSV for 202 images. SIIM-ACR PTX writes Frontal for all images, but 200 of 200 sampled DICOM files have ViewPosition PA or AP. The fixes are in their own harmonizers, not in base code.
    • MIMIC-CXR (DICOM) view_position: only with dicom_base_dir. The harmonizer then reads the DICOM tag ViewPosition of each file, which is slow (377,110 files for all splits). Without it, the harmonized table has no view_position. Decided (Frank Li, 2026-11-03, found in the 6c rewrite of the wiki page). The other options were to read the DICOM files in base_image_dir, and to take the view from the MIMIC-CXR-JPG metadata file. Before, the docstring said that dicom_base_dir falls back to base_image_dir, but the code never did. Checked by: tests/test_mimic_cxr.py::test_no_dicom_base_dir_gives_no_view_position.
    • MIMIC-Ext-CXR-QBA view_position: img.view_position of the question's image in image_metadata.parquet, with the shared names. With no image_metadata.parquet, the harmonizer warns and the table has no view_position. Decided (Frank Li, 2026-11-04, found in the 6c rewrite of the wiki page). The other option was no change. In q1M of A_frontal, the table and the source both give AP for 613,324 questions and PA for 386,676. Checked by: tests/test_mimic_ext_cxr_qba.py::test_view_position_comes_from_the_image_metadata and ::test_no_image_metadata_warns_and_gives_no_view_position.
    • Notes (OpenI view): since 2026-11-02, OpenI corrects the figure number with the DICOM tag (V-H2-40). The tag wins when it is AP or a lateral tag. A PA tag counts only on F1, because many lateral images also have PA. The 1,313 F1 images with no tag stay FRONTAL. Checked by: tests/test_harmonizer_data.py::test_openi_view_takes_the_dicom_tag_when_it_names_ap_or_a_lateral and ::test_openi_view_reads_the_dicom_tag.
    • 2-D view_position from the DICOM tag: a release can have no view column. Then the harmonizer reads the DICOM ViewPosition tag, as D-06 does for age and sex. Example: RSNA Pneumonia Kaggle has no view column, but in 300 of its DICOM files the tag is PA (166) or AP (134). Decided by the agent, for Frank Li to confirm (2026-11-02, Q-18 of the 2026-11-02 review). The other options were a view from a CSV only, and the tag only for datasets that a benchmark filters by view. Since 2026-11-03, RSNA Pneumonia Kaggle train and test read the tag. They read it with the sex and the age, in one header pass (extra_tags of add_patient_tags in radharmony/harmonizer/_dicom_tags.py). A real run gave train PA 14,511 and AP 12,173 (26,684 images), and test PA 1,618 and AP 1,382. Checked by: tests/test_rsna_pneumonia_kaggle.py::test_train_view_position_comes_from_the_dicom_tag and ::test_test_view_position_comes_from_the_dicom_tag.
    • Size columns: the BRAX extra columns rows and columns give the DICOM size from the source metadata, also in the PNG variant. Example: 2752 x 2232 in the table, but the PNG is 1261 x 1024. The BRAX wiki page says so. Decided by the agent, for Frank Li to confirm (2026-11-02, Q-10 of the 2026-11-02 review). The other options were the names dicom_rows and dicom_columns, and the PNG size in the PNG variant. Notes: since 2026-11-03, docs/wiki/reference/datasets/cxr-labels/brax.md says it (Q-10).
    • Emory CXR view_position: when the Frontal column and the DICOM ViewPosition tag disagree, Frontal wins, because it is more accurate (Frank Li). Frontal = 0 gives LATERAL. Frontal = 1 with ViewPosition Lateral gives NaN, because AP or PA is unknown. Decided (Frank Li, 2026-10-31, Q-14 of the 2026-10-31 review). The other options were NaN for every conflict, and both columns as in the source. Exception: Frontal = 0 with ViewPosition AP (2,202 images) gives NaN. In 24 random images of this group, 9 are upright frontal and 11 are decubitus (AP with the patient on the side). 3 are lateral, and 1 is unclear. So LATERAL is wrong for most of them.     D-05 Labels¶

    • Label columns are in LABEL_COLS, with snake_case names.
    • Name a label after the finding, not after the way the source codes it. Example: Montgomery and Shenzhen both give tuberculosis. Some datasets still use different names for one finding, for example ChestX-ray14 effusion and CheXpert pleural_effusion. Decided (Frank Li, 2026-11-05).
    • The label columns are sorted alphabetically by their snake_case names. BaseHarmonizer.harmonize sorts them. The cls vector uses the same order.
    • In cls, a label keeps the CheXpert-style source codes: 1 (positive), 0 (negative), -1 (uncertain) and NaN (not mentioned, or unknown). The probes use only 0 and 1, so they skip -1 and NaN. drop_uncertain=True drops the rows with -1. A harmonizer can keep raw grades, for example the TAIX-Ray grades 0 to 4. Then its dataset class maps them to 0 and 1.
    • Not mentioned (CheXpert, CheXpert Plus, MIMIC-CXR and MIMIC-CXR-JPG): the argument not_mentioned sets a blank label. "negative" (the default) gives 0, as most CheXpert papers do. "nan" keeps NaN, so the probes skip it. Example: Pleural Other is blank in 97% of the CheXpert train rows.
    • A regression target goes in REG_COLS, not in LABEL_COLS.
    • Each dataset wiki page gives the policy for uncertain and blank labels. For example, CheXpert maps a blank to 0 and keeps -1.
    • A row for which the labeler gave no label at all (an empty label list) gets NaN in every label. It is unknown, not negative. Example: 777 PadChest rows have the raw Labels value [''], and their reports name findings such as scoliosis. The probes skip NaN, so these rows do not count as negatives. A CheXpert-style row with every label blank is such a row, also with not_mentioned="negative". Example: 4,857 MIMIC-CXR-JPG train rows. Before 2026-11-02 they got 0 in every label (V-H1-41).
    • A source value that a harmonizer splits into one-hot columns gets NaN in all of these columns when the value is blank. Example: a blank RSNA 2024 lumbar severity gives NaN in normal_mild, moderate and severe, not 0 in all 3.
    • A class that a source does not annotate gets NaN, not 0. Example: the MedSeg dataset2 masks have only the values 0, 1 and 2, so pleural_effusion is NaN in its 829 rows. Decided by the agent, for Frank Li to confirm (2026-11-02, Q-12 of the 2026-11-02 review). The other option was 0 with the current wiki line.
    • A trigger word sets only its own finding. Example: the OpenI MeSH term Lung/hypoinflation does not set atelectasis. 189 of the 504 OpenI studies with atelectasis = 1 have only this term. Decided by the agent, for Frank Li to confirm (2026-11-02, Q-15 of the 2026-11-02 review). The other options were to keep the trigger with a wiki line, and a separate hypoinflation column.
    • Notes (MedSeg, since 2026-11-03): dataset2 gives NaN in pleural_effusion, because its masks have no class 3 (Q-12). Checked by: tests/test_harmonizer_data.py::test_medseg_dataset2_pleural_effusion_is_nan.
    • Notes (2026-11-02): OpenI no longer maps lung/hypoinflation to atelectasis (Q-15). Its reports with only the MeSH term "No Indexing", or with no term, get NaN in every label (V-H2-41).
    • Notes (2026-11-05): the Montgomery label tb became tuberculosis, the same name as Shenzhen and the public RadHarmony repo. Decided by Frank Li. The other option was to keep tb. A saved Montgomery table with tb has no tuberculosis column. With output_cls=True, the dataset class warns that the label column is missing, and a sample raises RuntimeError.     D-07 Box format¶

    A box is [dim0_min, dim0_max, dim1_min, dim1_max], row first. For a 2-D image this is [y_min, y_max, x_min, x_max]. A 3-D box adds dim2_min, dim2_max. The values are fractions in [0, 1] of the size of the image file that image_path points to. Each min is less than its max. bbox_labels has one label for each box, in the same order.

    A harmonizer clips each box to the image. It drops a box with no area left, with its bbox_labels and bbox_findings entries. Examples: a source box with x1 == x2, or a box past the image edge. It warns with the number of dropped boxes. When a box in ds[i] has a NaN or inf value, the transform raises a ValueError (MONAI wraps it in a RuntimeError).

    Why: the first axis of a numpy array is the row. So img[y0:y1, x0:x1] uses the box in its own order.

    D-36 Boxes of several readers are grouped by overlap¶

    When 2 or more readers draw boxes on one image, the harmonizer groups the boxes of one class that overlap (IoU > 0.5) into one lesion. It keeps a lesion that 2 or more readers drew. The box of the lesion is the mean of the boxes in its group.

    Example: VinDr-CXR train, image 03e6ecfa6f6fb33dfeac6ca4f9b459c9, class Nodule/Mass. 3 readers drew 55 boxes (28, 24 and 3). They form 40 groups, and 14 of them have boxes of 2 or more readers. So the table has 14 boxes.

    Why: the mean of all boxes of a class is on no real lesion when a reader draws more than 1 box. In VinDr-CXR train this is true for 2,179 of the 9,016 (image, class) pairs. Only in 96 of these 2,179 pairs (4%) is the mean box near a raw box (IoU > 0.5).

    • Status: Decided (Frank Li, 2026-10-29), option (c). The other options: (a) all 28,800 raw boxes, (b) weighted boxes fusion with the package ensemble_boxes, (d) no change. Findings: V-H3-4.

    D-28 The box in a sample matches the image in that sample¶

    In ds[i], the box always matches ds[i]["img"]. Every resize, pad, crop, flip and warp of the image moves the box in the same way. The box keeps the format of D-07, as fractions of the returned image. A sample box is an (N, 4) (2-D) or (N, 6) (3-D) float32 tensor, and (0, 4) or (0, 6) when there is no box.

    Example: a 2,000 × 1,000 (H × W) image is resized to 512 × 256. Then it is padded equally on the left and right to 512 × 512. A box with x_min = 0.0 in the table must have x_min = 0.25 in ds[i].

    D-43 A resample keeps the image centered¶

    D-27 A reader never clips pixel values¶

    A reader is the step that opens the image file. A reader never clips pixel values. Later transform steps can clip (D-14).

    Some readers must give an 8-bit image, for example reader="pil" for a Hugging Face processor. Such a reader scales a 16-bit image to 0 to 255 with the minimum and maximum of that image. Then it converts the image to RGB. An 8-bit image stays as it is.

    The VOI window of a DICOM file (D-13) is not a clip by the reader. It is the display step that the file defines. The dataset load and reader="monai" apply it to a MONOCHROME image after the file is read.

    Why: clipping makes most pixels of a 16-bit CXR white. Scaling with the minimum and maximum of each image also works for a 12-bit image that is stored in a 16-bit file. Division by 257 makes such an image very dark.

    • Status: Decided (Frank Li, 2026-10-28).

    Why: all probes then use the same features, so a score difference comes from the classifier only.

    D-29 The threshold comes from validation data¶

    The threshold for F1, accuracy, balanced accuracy, TPR, TNR, PPV, NPV and MCC comes from a validation set. The validation set is part of the training data, split by patient. The probe picks the threshold with threshold_strategy (for example, "youden"). It picks it one time for each seed in fixed-split mode, or one time for each fold in k-fold mode. Then it uses that threshold on the test set and on every bootstrap sample.

    Why: a threshold that is picked on the test labels makes every threshold metric too high. AUROC and AUPRC do not use a threshold.

    • Status: Decided (Frank Li, 2026-10-28). The validation set is 10% of the training patients (val_fraction=0.1, the same default as the fine-tune evaluator and the segmentation probes).
    • Checked by: J-06, tests/test_evaluator.py::test_threshold_comes_from_validation_data, and for zero-shot ::test_zero_shot_threshold_metrics_are_nan_without_a_fixed_threshold and ::test_zero_shot_uses_the_fixed_threshold.
    • Fit part: the 5 probes that train (linear, SVM, kNN, prototype, fine-tune) fit on the other 90% of the training patients. Example: with n_train=100 and one image per patient, a probe fits on 90 patients and picks the threshold on the other 10. D-40 says what n_train counts. A very small n_train can give NaN threshold metrics, because the validation part then has too few patients. Decided (Frank Li, 2026-10-30). The other option was a second model on 100% of the patients for the test scores.
    • Notes: a real run on 2026-10-30 used Shenzhen TB, RAD-DINO and the linear probe (5 folds, 3 seeds). For 50 to 200 patients, the AUROC with a fit on 90% and on 100% was 0.003 or less apart. At n_train=20, F1 was NaN.
    • Zero-shot: ZeroShotEvaluator has no train data, so it has no validation part. Its threshold metrics are NaN, unless threshold_strategy is "fixed:<value>". It gives one warning that says this. With negative prompts, the warning tells the user to pass "fixed:0", which means "closer to the positive prompts". AUROC and AUPRC do not change. Decided (Frank Li, 2026-10-30). The other options were a threshold from 10% of the test patients, and the threshold from the test labels with new metric names.
    • Notes (zero-shot): a real run on 2026-10-30 used MedSigLIP, VinDr-CXR test (3,000 images) and 19 labels with 20 or more positives. The mean balanced accuracy was 0.798 with the threshold from the test labels. It was 0.769 with a threshold from 10% of the test patients, and 0.767 with fixed:0.

Decided by the agent, for Frank Li to confirm (2026-11-02, Q-20 of the 2026-11-02 review). The other option was no change, because zero_shot.md already says it.

    D-19 Variance of a result¶

    • Fixed-split mode (train_dataset= and test_dataset=): n_seeds sets the number of train subsamples, each with its own seed. n_bootstrap sets the number of bootstrap samples of the test set.
    • K-fold mode (dataset=): the folds give the variance. The evaluator ignores n_seeds and n_bootstrap, and warns if you set them.
    • A result row with bootstrap = -1 is the point estimate.
    • The save_results() summary takes the mean over the point-estimate rows. It takes the std and the 95% CI over the bootstrap rows. With no bootstrap rows, it takes them over the folds or the seeds. With fewer than 2 values, the std and the CI are NaN: 1 value has no spread (V-E-31).
    • The std is the population std (np.nanstd, ddof=0), as cross_val_score(...).std() of scikit-learn gives. Example: 5 fold AUROCs give 0.043, and the sample std (ddof=1) gives 0.049. Decided (Frank Li, 2026-11-04, found in the 6c rewrite): keep it, and say it in the docs. The other options were the sample std everywhere, and the sample std over folds or seeds only.
    • A metric can be NaN in some folds or seeds, for example a threshold metric of a rare label (D-29). Then the summary gives for each metric the number of runs with a value (<metric>_n, for example f1_n = 4 of 5 folds). The probe warns one time for each such label, with the number of NaN runs.

    Why: a result shows how much the score changes with the train sample and the test sample. A mean over fewer runs must be visible in the result file, not only in the log.

    • Status: From the code (radharmony/evaluator/base.py). The summary rule: Decided (Frank Li, 2026-10-29, V-E-15). The count and the warning for NaN runs: Decided (Frank Li, 2026-10-31, Q-8 of the 2026-10-31 review). NaN std and CI for 1 value: Decided (Frank Li, 2026-11-02, V-E-31). The other options were a warning only, and another threshold rule when the validation part has too few positives.
    • Checked by: tests/test_evaluator.py::test_summary_mean_uses_point_rows_and_ci_uses_bootstrap_rows, ::test_summary_std_and_ci_need_2_values and ::test_summary_counts_the_runs_with_a_value_and_warns_once_per_label.
    • Notes: Frank Li approved the count and the warning on 2026-11-02 (Q-8), in _summarize of radharmony/evaluator/base.py. So the warning comes from save_results(), one time per label. Example: Label 'nodule': f1 is NaN in 1 of 5 runs. Their means use the other runs (D-19).

    D-41 The embedding cache holds features only¶

    Example: after a label fix (for example D-05: CheXpert keeps -1), a run with the old cache uses the new labels and the old features. The features do not depend on the labels.

    Why: a cache that also returns its labels makes a later run use old labels with no error.

    • Status: Decided (Frank Li, 2026-10-31, Q-6 of the 2026-10-31 review). The other options were a hash of the labels that raises ValueError when they differ, and labels from the cache with a doc line. The fingerprint: Decided (Frank Li, 2026-11-02, V-E-25).

    D-38 A report section falls back to the other section¶

When it has no IMPRESSION section, "impression" uses the FINDINGS text. When it has neither, "findings" and "impression" use the whole report. "both" joins the 2 sections, or uses the whole report when it has neither. "full" always uses the whole report.

    Why: each study with a report gets a reference, so no study is dropped.

So "new findings: none" in a sentence is not a header. Each section stops at the next header of its stop list in radharmony/evaluator/language/_report_parser.py, also on the same line. The FINDINGS list has IMPRESSION and CONCLUSION. Decided (Frank Li, 2026-10-30, V-E-8). The other option was a header at the line start only. Checked by tests/test_evaluator.py::test_report_parser_headers.
    • The fallback for a report with neither section uses the same header rule. So "No new findings: lungs are clear." in a sentence keeps the whole report (V-E-28, since 2026-11-03). Before, the fallback cut the report at that lowercase word. Checked by tests/test_evaluator.py::test_report_parser_headers.

FINDINGS: Heart is normal.", "impression" gives "Stable." and "both" gives "Heart is normal. Stable.". Decided (Frank Li, 2026-10-31, Q-9 of the 2026-10-31 review).     D-39 check_dataset: wrong values are ERROR, missing outputs are WARN¶

    check_dataset (radharmony/integrity.py) gives ERROR when a value breaks a rule:

    • No sample loads. This includes a dataset with 0 samples.
    • An image has NaN or Inf pixels.
    • A box is not 4 or 6 values in [0, 1] (D-07).
    • A box has a min that is not less than its max, for example a wrong axis order (D-07).

    It gives WARN when an output is not complete:

    • Some samples do not load, or a key is missing in some samples.
    • No sample has a requested output.
    • output_bbox=True, and no sample has bbox_labels (D-11).
    • Every label, mask or report is empty.

    scripts/check_datasets.py exits with code 1 when a dataset has ERROR.

    Why: wrong values break training with no error message, so a script or CI must stop. Missing outputs can be normal data.

    • Status: Decided (Frank Li, 2026-10-30, V-A-5). The other option was WARN for bad boxes and NaN or Inf pixels.
    • Checked by: tests/test_integrity.py::test_bad_values_change_the_status (with the 2 examples of "Box order"), ::test_requested_output_that_no_sample_has_warns, ::test_boxes_with_no_labels_warn, ::test_zero_samples_is_an_error. tests/test_scripts.py::test_check_datasets_zero_samples_exits_1 checks the exit code. tests/test_scripts.py::test_check_datasets_covers_dataset checks which script holds which spec.
    • Default run: a spec whose data has "status": "restricted" or "not_on_nas" in configs/data_paths.json gets default=False. It runs only when the user names it with --datasets. So a run with no --datasets can pass for every user. Decided (Frank Li, 2026-10-30). The other options were a run of every spec with a new result BLOCKED, and the default values from before 2026-10-29.
    • Box order: ERROR for a box with min not less than max. Example: [0.6, 0.2, 0.4, 0.1] (a wrong axis order) and [0.5, 0.5, 0.3, 0.3] (no area). Decided (Frank Li, 2026-10-31, Q-1 of the 2026-10-31 review). The other options were WARN, and no check.
    • Box labels: WARN when output_bbox=True and no sample has bbox_labels. Decided (Frank Li, 2026-10-31, Q-2 of the 2026-10-31 review). The other option was no check, because bbox_labels is an optional table column. Since 2026-11-01, every class that gives boxes also gives bbox_labels (V-D-29, V-H3-23). A real run on 2026-11-01 gave OK with both rules. It checked the 7 readable 2-D box datasets (25 samples each) and the 3 3-D box datasets (5 samples each).
    • Empty dataset: ERROR for a dataset with 0 samples. Each spec of check_datasets.py is a whole dataset with its default arguments, so 0 rows means a broken path, join or filter. Decided (Frank Li, 2026-11-02, Q-1 of the 2026-11-02 review). The other options were WARN with a line in this entry, and to leave the question open.

On that day, 35 of the 110 specs had default=False. 24 were restricted and 6 not on the NAS. The other 5 were Chest ImaGenome silver (3, slow) and the 2 Kaggle test classes of D-25.

    D-45 A known-problems list only gets shorter¶

    run_all.py --check-shrink <ref> fails when a known-problems list has an entry that the list at <ref> did not have, or a higher count. Only a new rule can add its old problems. You name each new rule: --check-shrink origin/main --new-rule L-013.

    Why: an old rule with 0 known problems has no entry in the old list, so the check cannot tell it from a new rule. Example: L-002 (no NAS paths in docs) has no entry today. A new NAS path in a doc page must fail, not join the list.

    • Status: Decided (Frank Li, 2026-11-01, V-A-38). The other options were to read the rule list of each check at <ref> (RULES.md, pyproject.toml, the STE rules), and no change.
    • Checked by: tests/test_evalkit.py::test_shrink_errors, ::test_shrink_errors_for_an_old_rule_with_no_entry and ::test_new_rules_come_from_the_pr_description.
    • CI: the PR description names each new rule on its own line, for example New rule: L-013. The CI step passes the PR description with --pr-body FILE. run_all.py adds the rule of each line to --new-rule. A line in a code block does not count. Decided (Frank Li, 2026-11-01). The other options were a CI failure that a maintainer merges by hand, and a file of new rules in the PR.
    • Named rules: a named rule that has an entry in the old list is not new, so its entries still may not grow.
    • Notes: a list with no file at <ref> belongs to a new check, so it cannot grow.
